# v0.3 results — one bucketed type, coset layers, symmetric truncation

*2026-08-30. Executes `research/plans/2026-08-29-v0.3-followups.md` (§1 → §4 →
§2 → §3, the decided order). Host, toolchain and caveats as in
`2026-08-26-v0.1-baselines.md` (ccqlin038, 32 threads, rustc 1.94.0), with one
extra caveat that applies to every number below: **the workstation was flagged
as possibly shared during this campaign**, and headline cases re-measured
minutes apart swung ±4–10%. Where it matters, both runs are quoted. Raw output:
`benchmarks/results/2026-08-29-ccqlin038/` (pre/mid-campaign) and
`benchmarks/results/2026-08-30-ccqlin038/v03-final.txt` (final, commit
`7be33f1`). Bitwise gates — the engine fingerprint net, thread-identity tests,
CSV byte-determinism — are immune to contention and were green at every step.*

## What landed, per section of the followups plan

- **§1** — the bucket-count floor is a fixed `DEFAULT_MIN_BUCKETS = 128`
  (`= 4×32`, the reference host's historical value, so every committed
  trajectory is reproduced). `B` is now a deterministic function of the term
  count alone; byte-identical output across machines is a property, not an
  accident of thread count. (`128890a`)
- **§4** — one bucketed `PauliSum`, canonical order `(bucket, key)`;
  `from_sum`/`into_sum`/`to_sum`/`propagate_bucketed` deleted; slice accessors
  replaced by `iter()`/`to_arrays()`/`bucket(b)` (user decision); `find` →
  `get`; `with_hash` re-partitions; `BuildAccumulator::finalize` picks the
  hash; single `finalize_layer` on `TruncationPolicy`. Python `propagate`
  stopped paying a per-layer flatten/rescatter round trip with zero binding
  changes. (`d1c16e4`)
- **§2 stage 1** — layers process cosets of `span(h(D))` in place with
  worker-persistent scratch; `begin_layer`/`end_layer`/`spare` (the `2n`
  double buffer) deleted; gather reads each input term once instead of
  `|D|` times; `Channel::support()` returns a `[u64; W]` mask.
  (`ee5ac70`, `e8a885d`)
- **§3** — `TopN` keeps the threshold tie group iff it fits entirely within
  `n`, else discards it whole; never splits a symmetry multiplet; an all-tied
  sum is deliberately wiped to empty. CSVs regenerated; sensitivity table now
  three-way. (`7be33f1`)

Two deliberate deviations from the plan text, both recorded in their commits:
the §3 rule is *keep-iff-fits* rather than always-discard (the literal rule
would have retained `n−1` on every all-distinct workload), and §2's delta-index
tag was **kept** although dropping it measured 5–14% faster — the Ising-CSV
condition in the pre-committed decision rule turned out to be an invalid proxy
(rotations/Cliffords merge ≤ 2 contributions per key, where any order is
bitwise-equal by commutativity), and a `GeneralUnitary2Q` probe proved the drop
breaks bitwise B-independence outright. The B-independence tests now include a
GU2Q case so this stays caught.

## 1. Headline: the v0.2 Trotter regression is erased, with a large margin

`propagate_trotter_step` — the one workload v0.2 recorded as a regression
(short circuit, no truncation, growing sum; the per-`propagate` conversion was
unamortizable):

| starting n | v0.1 | v0.2 | **v0.3** |
|---|---|---|---|
| 1 000 | 137.0 ms | 189.2 ms (regressed) | **18.8 ms** (re-run 18.8) |
| 10 000 | 863.8 ms | 1 195 ms (regressed) | **80.0 ms** (re-run 81.0) |

§4 removed the conversion entirely, so the driver is not merely un-regressed —
it is 7–11× faster than v0.1. This was the plan's cheapest large win and it
came in as designed.

## 2. Per-layer cost, n = 10⁶, 32 threads

| channel | v0.2 committed | v0.3 final (re-run) | vs v0.2 |
|---|---|---|---|
| `Clifford1Q::h` | 4.81 ms | 2.35 ms¹ | ~2.0× |
| `Clifford2Q::cnot` | 7.06 ms | **2.81 (3.28) ms** | 2.2–2.5× |
| `PauliRotation` (zz) | 6.83 ms | **4.77 (5.05) ms** | 1.35–1.4× |
| rotation, weight 4 | — | 4.97 ms¹ | (new case) |
| `Depolarizing` | 1.12 ms | 1.63–1.72 ms | **slower — see below** |
| `GeneralUnitary2Q` | — | 25.6–27.5 ms | (new case; open item) |

¹ from the scratch-pool campaign run (same tree, same day); the final sweep
did not repeat every non-headline case.

CNOT gains the most because §2 removed its 4-fold gather read amplification;
the rotation's 2-fold amplification was smaller to begin with.

`finalize_top_n` (keep 80% of 10⁶): 22.6 ms (v0.2) → **10.4 ms**, and the new
tie-heavy case (a 4-magnitude coefficient cycle, ~25% of the sum in the
threshold group) runs **9.0 ms** — the §3 group logic costs nothing; removing
the key tiebreak was indeed neutral-to-positive. `PauliSum::add` at 10⁶:
19.0 → 17.5 ms (per-bucket merge, no regression). `ingest_finalize_1e6`:
255 ms — `finalize` now hashes and bucket-sorts, absorbing what `from_sum`
used to cost; this is the one-time ingestion cost center now, recorded so it
does not surprise anyone profiling ingestion-heavy workloads.

## 3. Thread scaling, one rotation layer at 10⁶

| threads | 1 | 8 | 16 | 32 |
|---|---|---|---|---|
| v0.2 | 63.4 | 10.2 | 8.30 | 8.00 ms |
| v0.3 | 72.7 (72.9) | 9.39¹ | 5.28¹ | **5.93 (6.34) ms** |

Best-case scaling improves from 7.9× to ~12.3×, and the 32-thread absolute
number improves 1.26–1.35×. **Single-thread is 15% slower than v0.2** — the
coset machinery (span build, handle permutation, per-coset swaps, the tag
column) is pure overhead when there is no parallelism to buy with it. Some of
this delta may be contention (the pre-§2 run of the same tree measured
67–70 ms), but the direction is consistent across runs and is recorded as
real.

## 4. Memory at 10⁶ terms (W = 2): peak RSS roughly halves

Probe: deterministic 10⁶-term sum, ~30 alternating layers, measured with
`/usr/bin/time -v`; "pre-§2" is commit `d1c16e4`, which already had §4's
single representation but still carried the `2n` double buffer:

| variant | pre-§2 | §2 stage 1 | **v0.3 final** |
|---|---|---|---|
| cnot-only | 183.7 MB | 193.8 MB | **99.6 MB** |
| mixed + `TopN` | 229.6 MB | 275.8 MB | **135.1 MB** |

The reduction is §2's in-place layers *plus* the worker-scratch pool: stage 1
alone regressed the TopN-mixed case because `for_each_init` constructs its
init per rayon *split*, so MB-scale coset scratch was allocated and dropped
many times per layer; pooling scratch per worker (bounded by
threads × coset working set, retained across layers and calls) is what turned
the deleted double buffer into a realized ~45–50% RSS reduction. The Ising
example's RSS tells the same story in miniature: 50.4 MB (pre-§2) → 66.7
(stage 1) → **50.9 MB** (final).

## 5. End to end: the 2D Ising quench

| | v0.1 | v0.2 | v0.3 |
|---|---|---|---|
| 4×4 + 6×6 wall | ~157 s | ~34.5 s | **12.3 s** |

Two distinct causes, in order of arrival: the scratch pool (37.3 → 32.1 s with
*identical* physics — CSVs byte-for-byte), then §3 (32.1 → 12.3 s with
*changed* physics: whole-group discard keeps the sum strictly below the `TopN`
cap whenever the threshold group straddles it, so later layers are cheaper).
Those must not be conflated: most of the end-to-end factor is a physics-rule
change, not an engine speedup. The new CSVs are byte-deterministic across
repeated runs; the sensitivity of the answer to the tie rule is now quoted
three-way in `docs/examples/ising_2d_quench.md` — max Δ⟨X_avg⟩ 0.0049 (1.69%)
on 4×4 and 0.0012 (0.37%) on 6×6, the latter ~3× the spread between the two
pre-v0.3 tie-breaking choices. Tie handling matters more than v0.2's table
suggested.

## 6. Where v0.3 is slower, honestly

- **`GeneralUnitary2Q` at 10⁶, 32 threads: 25.6–31.8 ms across the campaign
  vs 21.0 ms on the pre-§2 tree** (single-thread is flat, ~8 threads is flat,
  32 threads anti-scales: ~30 ms at 8t vs ~34 at 32t). Its delta span has rank
  **2** under any hash (the sqrt-SWAP delta masks are {XX, ZZ, YY}-structured),
  so this is not the thin-granularity r = 4 case the plan worried about — it
  is a coset-working-set-vs-L2 question (4 swapped buckets + 4 fanout-16
  gather runs per task). Two fixes were tried and rejected by measurement:
  output-major gather at r = 2 (+17–18% — read re-amplification costs more
  than the write scatter) and the scratch pool (helped, from +48–56% down to
  +18–31%, but did not close it). Remaining leads: smaller
  `TARGET_BUCKET_LEN` for wide-fanout layers, NUMA placement of the pool.
- **Single-thread rotation +15%** (§3 above) — coset overhead with no
  parallel payoff.
- **`Depolarizing` 10⁶: 1.63–1.72 ms vs v0.2's committed 1.12 ms.** The
  rescale fast path was not touched by any v0.3 change and the delta was
  already present in the pre-§2 baseline run of the §1+§4 tree, so it is
  either a §4 storage-layout effect or machine state; unexplained, recorded,
  worth one clean-box re-measurement before anyone chases it.
- The §2 delta tag costs 5–14% on wide-delta 10⁶ layers and ~3–6% of Ising
  wall relative to a tag-less engine — paid deliberately for bitwise
  B-independence (see the deviations note above).

## 7. Still open after v0.3

The GU2Q 32-thread item and the depolarizing delta above; the 10⁴-scale layer
cases are healthy (all faster than pre-§2 after the scratch pool: h −22%,
cnot −32%, rotation −4%). `MIN_TERMS_PER_TASK = 64` and
`MIN_COSETS_FOR_PARALLEL = 2` remain unswept. The Python test suite has still
never executed on this host (no maturin/venv) — `test_general_unitary.py`,
`test_expectation.py`, and now the §3 docstring changes are compile-checked
only. v0.2 §7.1–§7.3 (amplitude tables, k-way run merge, L1 hashmap dedup),
the radix-partition flatten, and NUMA first-touch remain untried.
