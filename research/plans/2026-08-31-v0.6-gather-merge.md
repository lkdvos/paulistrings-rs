# v0.6 handoff: gather + merge are the bottleneck

Self-contained handoff for a fresh session. Everything referenced here is in
the tree at commit `590c187` or in `benchmarks/results/2026-08-30-ccqlin038/`.
Read `CLAUDE.md` first (v0.2–v0.5 status blocks); the v0.5 results note
(`research/notes/2026-08-30-v0.5-results.md`) is the immediate predecessor of
this document and already names "merge is now the dominant busy phase" and
"in-place cos-scaling of the id stream" as the open items this plan turns into
work.

## 1. Where the time goes (v05-S2 probe, n=10⁶, W=2, ccqlin038)

Source: `benchmarks/results/2026-08-30-ccqlin038/v05-S2-probe.json` (one JSON
object per line; regenerate with
`cargo run --release --features phase-timing --example phase_breakdown`).
All numbers below are **CPU-ms per layer** (busy time summed over workers),
because that is what inflates; wall ms/layer in parentheses.

| cell | t | gather | sort | merge | busy total (wall) | idle% |
|---|---|---|---|---|---|---|
| rotation_zz | 1 | 24.5 | 3.6 | 19.0 | 47.2 (47.4) | 0 |
| rotation_zz | 32 | 49.8 | 8.6 | 38.9 | 98.0 (3.44) | 8.1 |
| trotter | 1 | 32.9 | 7.4 | 33.6 | 74.1 (81.1) | 0 |
| trotter | 32 | 137.2 | 20.7 | 101.8 | 262.3 (9.84) | 4.9 |
| gu2q | 1 | 50.3 | 48.2 | 43.3 | 142.1 (142.4) | 0 |
| gu2q | 32 | 142.7 | 110.9 | 141.9 | 397.5 (13.1) | 3.8 |
| cnot | 1 | 21.8 | 9.2 | 10.9 | 41.9 (41.9) | 0 |
| cnot | 32 | 42.9 | 16.2 | 24.3 | 83.7 (2.97) | 9.7 |

Row-volume facts (per layer, from the same probe): rotation_zz gathers 2.5M
rows (1.5M id + 1.0M sorted rest) from 1.5M terms; trotter 3.16M (2.72M id +
0.44M rest) from 2.72M; gu2q 7.75M (2.13M id + 5.62M rest) from 2.12M;
cnot 1.0M (0.25M id + 0.75M rest) from 1.0M.

What this says:

- **Gather + merge are 75–92% of busy everywhere** (sort only matters on gu2q
  at 28–34%). Swap/size/clear are noise (<1%). Idle is single digits — this
  is not a load-balance problem.
- **The bottleneck is not the 1t cost but the inflation with threads.** Phase
  *shares* stay flat while total busy time grows 2.0× (rotation, cnot), 2.8×
  (gu2q), 3.5× (trotter) from 1t → 32t: every worker's per-row cost rises
  under contention. Per-row: trotter's merge goes ~10.6 → ~32 ns/row,
  gather ~10.4 → ~43 ns/row.
- **Two confounds to keep separate when measuring:** (a) 32t = 2
  hyperthreads/core on this box, so ~1.4–2× inflation at 32t is core sharing,
  not memory; the 16t column is the cleaner memory/coherence signal (rotation
  1.18×, cnot 1.55×, gu2q 1.77×, trotter 2.08× vs 1t). (b) trotter at 32t
  already moves ~36 GB/s attributable DRAM against the measured ~45–49 GB/s
  box ceiling (v0.4 baseline note; `bandwidth.txt` in the results dir) — it
  is genuinely near the memory wall, so for trotter only **traffic
  reduction** can win; for rotation/cnot (far below the ceiling) latency and
  per-row overhead are still on the table.

Conclusion: the highest-value work is (1) cutting bytes moved per row through
gather→merge, (2) cutting per-row ALU/branch cost in the two hot loops. NUMA
placement is real but deferred (see §5 and the N1 negative result before
touching it).

## 2. Code map

The per-coset pipeline is `fill_coset`
(`crates/paulistrings/src/engine/bucketed.rs:389`): swap → size → gather →
per-run { sort rest → `merge2_into` } → clear. One coset of `span(h(D))` per
Rayon task via `par_chunks_mut(m)`; cosets are write-disjoint.

- `GatherRun` (`bucketed.rs:143`): six columns — `id_x/id_z/id_coeff` (the
  identity-delta stream: keys untouched, inherits the source bucket's
  strictly-ascending unique order, **never sorted**) and `x/z/coeff` (the
  rest stream, sorted per run).
- Gather variants: `gather_local_input_major` (`bucketed.rs:595`, the path
  every built-in takes — `GATHER_OUTPUT_MAJOR_MIN_R = 3` is never reached by
  a built-in), `gather_local_output_major` (`bucketed.rs:639`, unmeasured
  guard for rank ≥ 3 custom channels), and the inline rotation gather inside
  `fill_coset` (`bucketed.rs:498`).
- `merge2_into` (`crates/paulistrings/src/engine/sort_merge.rs:545`): fused
  two-pointer merge of id + rest with segmented reduction, id-first on key
  ties, zero-drop and `keep_term` on the fully summed coefficient, exact-zero
  cos rows kept until the reduction (signed-zero contract — see its doc).
- `sort_rows_with_scratch` (`sort_merge.rs`, near `SortScratch`): permutation
  sort on worker-persistent scratch. **Its `sort_by` must stay the stable
  adaptive sort** — runs are concatenations of piecewise-sorted streams and
  `sort_unstable_by` measured +77% on rotation_zz (recorded in the fn doc).
- Key-preserving channels (depolarizing/dephasing/Pauli) bypass all of this
  via `rescale_in_place` (`bucketed.rs:686`) — out of scope.
- Traffic model (per layer, T = 16W+16 bytes/row):
  `terms_in×T + 2×rows_gathered×T + 2×rows_sorted×T + terms_out×T`
  (`scripts/perf-viz.py::dram_metric`, `benchmarks/PROFILING.md`). The
  `2×rows_gathered×T` term is gather-write + merge-read — the target of G1.

## 3. Binding constraints (do not rediscover these the hard way)

1. **Determinism policy (user directive, broadened 2026-08-31):** bitwise
   output preservation is **not required anywhere**. The correctness bar is
   agreement to floating-point tolerance (`assert_terms_close` and the
   differential tests against the v0.1 oracle); equal-key summation order is
   free to change. The byte-exact tests in the tree (thread-count/repeat-run
   determinism, the fingerprint net
   `engine/bucketed.rs::layer_fingerprints_are_stable`) are convenience
   tripwires: when one trips under a change that is correct to tolerance,
   regenerate its literals or demote it to `assert_terms_close` in the same
   commit with a one-line note. Do not design or reject optimizations to
   keep output bits stable.
2. **Signed-zero contract:** a θ = π/2 rotation emits `cos·coeff = ±0.0` id
   rows; the only zero test is on the final accumulator (`merge2_into` doc,
   test `merge2_cancellation_and_signed_zero`). Any id-stream rework must
   keep this.
3. **TDD policy** (CLAUDE.md): red → green → refactor per slice, one commit
   per slice, workspace green + clippy `-D warnings` under **both** feature
   configs (`--features phase-timing` too) at every boundary.
4. **Measurement discipline:** `--release` only, canonical host ccqlin038,
   `scripts/bench-campaign.sh <slice-name> criterion:apply_layer_bucketed probe:`
   then `scripts/perf-viz.py <prefix> --compare .../v05-S2.json`; never build
   while a measurement runs; the box is shared — check loadavg, note it.
   Baseline = `v05-S2.{json,-probe.json}`. Keep-only-if-measured-faster
   applies to every slice here.

## 4. Candidate work, in priority order

### G1 — borrow the id stream instead of copying it (biggest modeled win)

Today the identity pass **materializes** a copy: gather writes each id row
into `id_*` (2T bytes: T write + later T merge-read), yet that stream is
exactly the source bucket `old[j ^ coord_identity]` in order, with a per-row
coefficient transform (rotation: `c` if the term commutes with the generator,
`c·cos` otherwise; Local: `c · deltas()[0].amp[support_bits]`, skipping
zero-amp rows) — and `old` survives untouched until the end of the coset
task, disjoint from the `dst` columns (they were swapped).

Change: drop the `id_*` columns from `GatherRun`; make `merge2_into` (or a
new `merge2_from_source`) take the a-stream as *borrowed slices of the source
bucket* plus a per-row coefficient map (an enum over {rotation
commute/cos-scale, local amp-lookup, plain} — avoid a generic closure only if
it stops inlining; measure). Gather then only writes the rest stream.

- Modeled traffic cut (2 × id_rows × T): trotter **−42%** of layer bytes
  (261 of 617 MB/layer), rotation_zz −30%, gu2q −14%, cnot −7%. Trotter is
  the memory-wall cell, so this should convert to wall time nearly 1:1 at
  32t.
- The per-row ALU it re-adds (recomputing `support_bits`/`commutes_with` in
  the merge) was already paid once in gather and is cheap against 96 bytes of
  DRAM per row saved.
- Correctness invariants carry over: source bucket is strictly ascending
  unique (the debug assert moves to the borrowed stream); zero-amp id rows
  are skipped inline exactly as gather skips them today; signed-zero rows
  flow to the accumulator as before. Verify with `assert_terms_close`
  differential tests against the current pipeline.
- Watch: `rows_gathered`/`rows_sorted` semantics in `PhaseStats` and the
  perf-viz DRAM model must be updated together (id rows are no longer
  written/re-read — a new `rows_id` counter or a model change; keep
  `benchmarks/PROFILING.md` in sync), and `size_ns`/capacity sizing loses the
  id half.

### M1 — segment-copy fast path in the merge

`merge2_into` pays a two-pointer compare + branch per row even where one
stream locally dominates. For trotter the rest stream is 14% of rows: long
stretches of the id stream pass through untouched. Change: between
consecutive rest keys, locate the id-stream boundary (gallop/exponential
search) and bulk-process the id segment — `extend_from_slice` the key
columns, per-row loop only for coefficients (mandatory under G1's transform;
also where `keep_term`/zero-drop live). Also specialize the two trivial
shapes: empty rest (pure id pass-through — trotter's commuting-heavy layers)
and empty id (delegate to `merge_into`, which already exists).

- Expected: merge is 39–45% of busy on rotation/trotter; cutting its per-row
  branch cost matters most at high t where per-row cost triples. No modeled
  traffic change — this attacks the ALU/branch side, so measure at 1t and
  16t separately to see it.
- Design M1 *with* G1 (one signature change, not two): G1 decides what the
  a-stream looks like; M1 is a loop-structure change inside the same
  function.

### G2 — interleaved key layout in the transient run (locality)

`GatherRun` and the sort/merge touch `x` and `z` as **separate** arrays: every
key comparison and every row copy hits two independent streams (four in the
merge's a-vs-b compare). The destination `PauliSum` layout is a public
invariant (SoA, GPU story — do not touch), but the *transient* run is free:
store keys as one `Vec<[u64; 2W]>` (x words then z words — lex order over the
concatenation is unchanged, so `Ord` semantics survive). Halves the open
write streams in input-major gather (helps gu2q, which chose input-major at
the L2 cliff), halves random streams in the perm-sort's comparator (gu2q sort
is 28–34% of busy), and simplifies the merge compare. Cost: one
interleave→SoA split when writing `dst` (sequential, cheap) and a mechanical
API churn through `sort_rows_with_scratch`/`merge2_into`.

- Pure layout change, output unaffected up to the usual tolerance. Measure
  on gu2q first — it has the most sort and the most gather streams; if gu2q
  doesn't move, don't land it.

### Deliberately deferred (do not start without new data)

- **NUMA / placement:** N1 (static coset→worker assignment) measured
  1.25–1.9× *slower* than work-stealing and was reverted — read the v0.5
  results note §Track N before any placement work. The recorded future
  variant needs intra-socket stealing + a stable socket-level partition +
  first-touch of bucket columns. Only worth attempting after G1: if G1 pulls
  trotter well off the bandwidth ceiling, the payoff shrinks.
- **Knob sweeps:** `MIN_COSETS_FOR_PARALLEL = 2` and
  `GATHER_OUTPUT_MAJOR_MIN_R = 3` are unswept. Cheap to sweep with the
  campaign; low expected value; fine as a filler slice.
- **cnot idle (9.7% at 32t)** and the §8.3 small-sum hashmap fast path:
  known, unchanged, out of scope.

## 5. Suggested order and success criteria

1. **G1** (with the M1 signature designed in): gate = trotter 32t probe
   wall < 8 ms/layer (from 9.84) and modeled DRAM GB/s visibly down;
   rotation_zz 32t < 3.0 ms.
2. **M1** loop restructure: gate = merge busy-share down on trotter/rotation
   at 1t *and* 16t without gather regressing.
3. **G2** on gu2q data: gate = gu2q criterion `apply_layer_bucketed` −10% or
   don't land.
4. Campaign + results note `research/notes/<date>-v0.6-results.md` in the
   style of the v0.5 note (per-slice numbers, negative results recorded),
   update the CLAUDE.md status block, republish the perf-report artifact
   (`scripts/perf-viz.py ... --compare` → the existing artifact URL is in the
   session that owns it; a new session can find it via the Artifact tool's
   list action, title "Paulistrings Perf Report").

Every slice: keep-only-if-measured-faster, one commit, tests+impl together,
suite green under both feature configs.
