# v0.2 — TDD slice plan

*2026-08-26. Companion to `2026-08-26-v0.2-gf2-bucketing.md`, which is the source
of truth for **what the code does**. This file is the source of truth for
**order of work** and the **test contract per slice**. Same relationship as
`2026-04-30-v0.1-tdd-slices.md` bore to the v0.1 scope doc.*

## Policy

Unchanged from v0.1 and from `CLAUDE.md`:

1. **Red.** Smallest failing test that pins the behaviour. Unit tests next to the
   code in `#[cfg(test)] mod tests`; cross-module behaviour in
   `crates/paulistrings/tests/`.
2. **Green.** Minimum to pass. No speculative helpers for later slices.
3. **Refactor.** Only after green.

- Assert against hand-computed values, or against the v0.1 engine as an oracle
  (§9.2) — never against another `todo!()`.
- Parameterize over `W ∈ {1, 2}` for anything touching multi-word logic.
- `cargo test --workspace` green and `cargo clippy --workspace --all-targets
  -- -D warnings` clean at **every** slice boundary.
- Benchmarks follow tests. Never tune a `todo!()`.
- **At every phase boundary: pause, summarize, check in with the user, and commit
  the phase as a single logical unit only after they confirm.** Do not roll
  phases together; do not start the next phase before the current one is
  committed.

Two additional rules specific to v0.2:

- **Nothing merges without the differential test passing** once slice B.5 lands.
  The v0.1 engine is the oracle; a new-engine result that disagrees is a bug in
  the new engine until proven otherwise.
- **No silent bounds.** If a slice caps coverage (a fallback threshold, a skipped
  channel, a sampling limit), it says so in the commit message and in
  `research/notes/`.

## Phase A — design and baselines

No production code. Establishes what "faster" will mean.

**A.1 — Baselines on the current tree.** `cargo bench -p paulistrings`, plus a
timed `cargo run --release --example ising_2d_quench`. File raw output under
`benchmarks/results/<date>-<machine>/` (gitignored) with a committed summary in
`research/notes/`, including commit hash, CPU, cache sizes, NUMA topology,
toolchain, thread count and governor state.

**A.2 — Extend the bench surface before optimizing.** The only layer benchmark
today is `Clifford1Q::h` at fanout 1 — which happens to be the *worst* case for
`sort_phase` and the *best* case for `merge_phase`, so it measures exactly one
point. Add:
- `PauliRotation` (fanout 2; the dominant channel in real Trotter circuits).
- `Clifford2Q` (`cnot`).
- `Depolarizing` (the pathological case: a coefficient rescale behind a full sort).
- A multi-layer `propagate` over a realistic circuit.
- Explicit `rayon::ThreadPoolBuilder` sweeps at 1/2/4/8/16/32 threads, since §7's
  scaling claim is untested and the host has 2 NUMA nodes.
Re-baseline after adding.

**A.3 — Documents.** The v0.2 design doc; this file; the `§5` post-mortem note;
`§5`/`§9` of the v0.1 scope doc marked superseded with a pointer.

**Check in.**

## Phase B — single-threaded implementation

Strictly sequential. Every `par_iter` in the new engine is a plain `iter` until
Phase C, so correctness is established before parallelism can obscure it.

**B.1 — `Gf2Hash<W>`** (§3)
- Construction from `(num_qubits, b, seed)`; reproducible rows.
- Tests: `bucket_of` is in `0..2^b`; **linearity** `h(v ⊕ w) = h(v) ⊕ h(w)` as a
  proptest over `W ∈ {1,2}`; `h(0) = 0`; columns beyond `num_qubits` are masked
  (a key with bits set outside `num_qubits` cannot influence the bucket);
  `refine`/`coarsen` are prefix-consistent, i.e. `h_b` is the low `b` bits of
  `h_{b+1}`; occupancy is balanced on a low-weight input set (guards §3.2 — this
  is the test that would have caught a coordinate-projection `H`).

**B.2 — `BucketedSum<W>`** (§4)
- `from_sum`, `into_sum`, `len`, a bucketed `assert_invariants`.
- Tests: `into_sum(from_sum(s)) == s` bitwise, as a proptest; the bucketed
  invariant holds after `from_sum`; `into_sum` output satisfies
  `PauliSum::assert_invariants`; empty and single-term sums; `num_qubits` not a
  multiple of 64.
- `rebucket`: refine splits each bucket in two preserving within-bucket order;
  coarsen merges pairs; both round-trip; `len` unchanged by either.

**B.3 — `PauliRotation` support hygiene** (§5.3)
- Derive support from the generator; validate any caller-supplied value.
- Tests: a generator whose bits fall outside the declared support is rejected (or
  the support is corrected — pick one and pin it); existing rotation tests
  unchanged; multi-word generators.

**B.4 — `Prepared` and `Channel::prepare`** (§5)
- `Prepared::derive_local` by probing `apply` on the `4^k` local basis Paulis;
  `Channel::prepare` defaulting to it; `PauliRotation` override for weight > 2.
- Tests: for **every** built-in channel, the derived table reproduces `apply` on
  randomized *full-width* inputs (proptest) — this is the §5.3 soundness net;
  the derived `dim D` matches the §2.3 table exactly, per channel, forward and
  adjoint; `bucket_delta` grouping is correct including a forced-collision case
  (small `b`, so `rank(H|_D) < dim D` and a group has >1 member).

**B.5 — `apply_layer_bucketed`, sequential** (§6)
- Gather + reused `sort_phase` + `merge_chunk` refactored to append into
  `&mut Vec`s.
- Tests: **the differential proptest against `sort_merge::apply_layer`** over
  random sums × every channel × every policy, forward and adjoint — the primary
  correctness net. Plus the bucketed invariant after every layer; the
  `mask == 0` in-place-rescale short circuit agrees with the general path;
  exact-zero runs dropped; `keep_term` applied to the *summed* coefficient
  (port `threshold_applied_after_summation`).

**B.6 — `finalize_layer_bucketed`** (§8)
- Default via `into_sum`/`from_sum`; overrides for `TopN`, `And`, `Or`.
- Tests: `TopN` keeps exactly the `n` largest by magnitude and preserves
  within-bucket order (port `top_n_preserves_sort_order`); port
  `propagate_top_n_truncates_each_layer`; `And`/`Or` composition matches the
  unbucketed policy on the same input; the default path is exercised by a
  custom policy defined only in the test.

**B.7 — `propagate` on the bucketed path** (§4.1)
- Tests: **all 17 `tests/propagate.rs` tests pass unmodified**, including
  `apply_layer_identity_channel_passes_sum_through` (whole-slice equality) and
  `apply_layer_combines_inputs_that_collide_under_channel` (positional indexing
  of globally-sorted output). Heisenberg still reverses channel order and applies
  adjoints. Small-`n` fallback to the v0.1 path is exercised and agrees.

**B.8 — `AmplitudeDamping::apply_adjoint`** (a real correctness fix)
- Currently inherits the default `apply_adjoint = apply`, documented at
  `noise.rs:114-119` as a knowingly-wrong approximation — a silent trap for
  Heisenberg backpropagation.
- Tests: forward-then-adjoint round-trip on a known input; the adjoint's derived
  PTM is the conjugate transpose of the forward one; the existing forward tests
  unchanged.

**B.9 — `GeneralUnitary1Q/2Q`** (§5.1)
- Replace both `todo!()`s; make both generic over `W` (they are currently
  hardcoded `impl Channel<1>`); expose in Python.
- Tests: a Clifford expressed as a general unitary agrees with the corresponding
  `Clifford1Q`/`Clifford2Q` table; a random unitary's PTM is trace-preserving and
  its derived `dim D` matches §2.3 (2 and 4); `W ∈ {1,2}` including a
  word-boundary support; the differential test extends to cover them.

**B.10 — `expectation` / `overlap`**
- Public API on `PauliSum` (and the bucketed form, where it is a per-bucket
  reduction). `examples/ising_2d_quench.rs:104-113` drops its hand-rolled
  version.
- Tests: agrees with the hand-rolled reference on the example's own inputs; the
  example still reproduces `examples/output/ising_{4x4,6x6}.csv`.

**Check in.** Expect little or no speedup from Phase B — possibly a regression.
The wins here are the removed allocations and the emptied inner loop; the sort is
*relocated*, not removed. The speedup is a Phase C result.

## Phase C — parallelism and measurement

**C.1 — Bucket-parallel driver** (§7)
- `par_iter_mut` over output buckets; per-thread scratch pool.
- Tests: output is **byte-identical across thread counts (1/2/4/8/32) and across
  bucket counts `B`** — the strengthened §9.1 contract, and stricter than v0.1's
  `scan_determinism_across_thread_counts`. Verify the canonical delta ordering is
  what makes the `B`-independence hold, by asserting it directly.

**C.2 — Measure and profile.** Re-run A.1/A.2 against the new engine. Profile
with `perf`/`cargo-flamegraph`. Record findings — including anything that came
out *slower* — in `research/notes/`. That directory should stop being empty.

**C.3 — Work the §7.1–7.3 list, in profile order only.** No untargeted tuning;
this is the mistake v0.1's slice 11.3 encoded by being two lines long. Each item
gets a before/after number or an explicit "measured, not worth it" note.

**C.4 — Constants and placement** (§7.4). `TARGET_BUCKET_LEN`, rehash hysteresis,
small-`n` fallback threshold, NUMA first-touch. Verify §7's near-linear scaling
claim on a real workload, and if it does not hold, say so and say why.

**Check in.**

## Out of scope for v0.2

- GPU backend (§10 keeps the door open; nothing more).
- Distributed / MPI, though §10 now has a concrete mechanism for it.
- Widths beyond `W = 16`.
- Removing the v0.1 engine. It stays as the oracle and the small-`n` fallback
  until there is a measured reason to drop it.
