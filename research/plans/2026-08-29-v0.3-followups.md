### Closed: SIMD linalg (comment 2)

`matmul`/`trace`/`dagger` in `channel/unitary.rs` are called from exactly one
place — `from_matrix` — which runs **once per channel at circuit construction**.
A 2Q gate is 256 trace computations of 4×4 matmuls: microseconds, once. A
`nalgebra`/`faer` dependency buys nothing measurable.

If SIMD is wanted, the hot loops are the gather inner loop (complex multiply +
XOR over `W` words, `engine/bucketed.rs::gather_local`) and
`Gf2Hash::bucket_of` (`b × 2W` AND+popcount). Note
`research/ideas/2026-04-30-representation-options.md` flagged SIMD in v0.1 and
nothing came of it.

## §1 — Decouple `B` from the thread count (do first; small, unblocks §2)

`engine/mod.rs::default_min_buckets()` is `4 × rayon::current_num_threads()`, so
the bucket count depends on the thread count. That is the *only* reason
bitwise-identical-across-`B` had to be a hard constraint, and that constraint
cost real things: the flat delta ordering instead of grouping by bucket delta
(giving up input-bucket locality, see v0.2 §5.1), the `TopN` key tiebreak, and it
blocks §2 below.

**Do:** make the floor a fixed constant. `B` then becomes a deterministic
function of `n` alone.

**Keep:** byte-identical output across thread counts. Different answers on
different machines is a real trap. It follows from write-disjointness plus a
stable per-bucket sort, and needs no `B`-independence once `B` stops depending on
threads.

**Demote:** `B`-independence, from load-bearing invariant to a property that is
still tested but may be broken deliberately when something is worth more.

Tests affected: `output_is_byte_identical_across_bucket_counts` and
`top_n_is_bucket_count_independent_on_tied_magnitudes` in
`engine/bucketed.rs` — keep them running but they stop gating design choices.

## §2 — Coset tasks, and in-place layers

### The structure

`h(D)` is a linear subspace of `GF(2)^b` of dimension `r`. Output bucket `β'`
reads exactly the **coset** `β' ⊕ h(D)`. Cosets partition the bucket index space,
and every output bucket in a coset reads that *same* coset — so a coset is a
closed, independent unit of work.

Concretely for a Pauli rotation (`h(D) = {0, δ}`): outputs `β` and `β ⊕ δ` both
read inputs `{β, β ⊕ δ}`. The pair is self-contained; the bucket space splits
into `B/2` such pairs.

### What it buys: read amplification goes away

Today a task = one output bucket, reading `2^r` input buckets, so total gather
reads are `|h(D)| · n` — 2× for a rotation, 4× for `CNOT`, 16× for
`GeneralUnitary2Q`. v0.2 §6.1 documents this as the inherent price of gathering
rather than scattering.

A task = one coset reads its `2^r` input buckets **once** and scatters into its
`2^r` output buckets. Total gather reads drop to **`n`**. This is the fix for
§6.1, and it is the largest measured win still on the table.

### What it also buys: in-place, with per-thread scratch

Because a coset's input and output bucket *index sets coincide*, a task can work
in place:

1. Swap the coset's `2^r` bucket column-triples with the thread's scratch
   triples (`std::mem::swap`), so the thread holds the old data and the buckets
   hold empty, capacity-retaining `Vec`s.
2. Gather from scratch, sort, merge back into those same bucket slots.
3. Clear the scratch for the next coset.

Peak memory goes from `2n` (the current front/back double buffer in
`bucket/sum.rs::begin_layer`) to `n + O(threads × 2^r × n/B)` — at 32 threads,
`r = 1`, 1024 terms/bucket that is ~3 MB of scratch against a ~48 MB second copy
at 10⁶ terms, `W = 2`.

This is only possible because the coset framing makes the read/write dependency
*local*. In the current per-output-bucket gather, different outputs read
different input sets, so no input bucket can be freed until every output that
reads it is done — hence the double buffer.

`begin_layer`/`end_layer` and the `spare` field can go away.

### Costs to watch

- **Parallel granularity** drops from `B` tasks to `B/2^r`. Fine at `r = 1`
  (rotations, noise, 1Q Cliffords); thin at `r = 4` (`GeneralUnitary2Q`) on 32
  threads. May want to keep the per-output-bucket path for large `r`.
- **Summation order** becomes input-bucket-ordered rather than delta-ordered.
  Restore a canonical order with a stable tiebreak on the delta index in the
  per-bucket sort (an extra `u8` column in the scratch). This is only needed for
  reproducibility across `B`, which §1 demotes — decide whether to pay for it.
- The algebra above has been **verified on paper, not implemented or measured**.

### Comment 1 rides along here

`PauliRotation` stores `support: Vec<u32>`, which is fully derivable from
`gen_x | gen_z`. It exists only because `Channel::support()` returns `&[u32]`, a
borrow, so something must own it. It has exactly **one** non-test call site —
`channel/prepared.rs:234` in `derive_local`, once per layer.

Change `support()` to return a bitmask (`[u64; W]`) instead of qubit indices. The
engine wants bits anyway: `derive_local` immediately converts the indices back
into masks. That deletes the field and removes a conversion.

## §3 — `TopN` discards whole tie groups

**Decision: discard.**

Current behaviour (`truncation/builtin.rs`) breaks ties by `|coeff|` descending
then **key** ascending. That is not merely arbitrary, it is *systematically
symmetry-breaking*: terms related by a lattice symmetry have exactly equal
magnitude, and lexicographic key order has nothing to do with the symmetry, so
keeping some multiplet members and not others yields a truncated operator that is
not symmetric. This is why the 2D Ising example produces so many exact ties.

New rule:

1. Find the threshold magnitude `t` (the `n`-th largest).
2. Keep every term with `|c| > t`.
3. **Discard the entire tie group at `|c| == t`.**

Consequences:

- Retains **at most** `n`, so `TopN`'s memory-bounding purpose is preserved —
  discarding is the safe direction. Keeping the group instead could overshoot
  without bound (all-equal coefficients would keep everything).
- Retained count becomes data-dependent. Update the docs; `TopN(n)` now means
  "at most `n`, without splitting multiplets".
- **Edge case to guard:** if every coefficient has equal magnitude, step 2 keeps
  nothing and the sum is wiped. Needs a floor — keep the group, or fall back to
  the old behaviour, but pick deliberately and test it.
- The key tiebreak disappears from both implementations, which *simplifies* the
  code.

Apply to both `TopN::finalize_layer` and `TopN::finalize_layer_bucketed`, keeping
them in agreement.

**This changes physics output.** `examples/output/ising_{4x4,6x6}.csv` must be
regenerated, and `docs/examples/ising_2d_quench.md`'s truncation-sensitivity table
re-measured (it currently quotes max Δ⟨X_avg⟩ of 0.0053 for 4×4 and 0.00037 for
6×6 between two tie-breaking choices; this adds a third).

Performance of the tiebreak was never isolated — the `then_with` is lazy so it
costs nothing when magnitudes differ, but it was not measured on tie-heavy data.
Removing it should be neutral-to-positive; measure with
`finalize_top_n` in the bench harness.

## §4 — One bucketed representation

**Decision: `PauliSum` becomes bucketed. `BucketedSum` and the flat type merge.**

### The canonical order

**Sorted by `(h(v), lex(x, z))`** — bucket index ascending, then Pauli key
ascending within a bucket. This is promised publicly, not an implementation
detail.

The property that makes this work: **a single-bucket sum is automatically in
plain lex order**, because `h(v) = 0` for every term. So the v0.1 order is the
`B = 1` special case of the new one.

That is not a corner case in practice. `desired_bits(len, 1024, min_buckets)`
returns **0 bits for any sum below `min_buckets × MIN_TERMS_PER_TASK` terms**, so
every small sum — which is every test fixture in the crate — has one bucket and
therefore the old order. The ~17 positional integration tests
(`out.x()[0]` and friends in `tests/propagate.rs`,
`tests/propagate_bucketed.rs`) should pass unchanged. Verify this early; it is
the assumption the whole refactor rests on.

### What this deletes

- `from_sum` / `into_sum` / `to_sum` and the `B`-way merge entirely. Iteration in
  canonical order is now just concatenating buckets in index order, `O(1)`
  bookkeeping. **This removes the 78 ms `to_sum` cost measured at 10⁶ terms**,
  which was the single most expensive operation in the design.
- `propagate` vs `propagate_bucketed`: one entry point again.
- `refill_from_sum`, and the round-trip default in
  `TruncationPolicy::finalize_layer_bucketed` (v0.2 §7.6 / open question 5).
- The per-`propagate` conversion cost, and with it the
  `propagate_trotter_step` regression recorded in v0.2 results §5.

### What gets faster

- `find`: hash the key, then binary-search **within its bucket** — a smaller
  search than the current global one.
- `add`: per-bucket merge, parallel. Requires both sums to share `H`
  (`Gf2Hash::same_rows_as` already exists); decide the error behaviour when they
  do not.

### What needs care

- `assert_invariants` becomes the current `BucketedSum` version: bucket count
  matches the hash, every term in its own bucket, strictly ascending key within
  each bucket, `is_within(num_qubits)`, cached length agrees.
- NumPy export order becomes `H`-dependent for multi-bucket sums. Check
  `python/paulistrings/tests/test_numpy.py`, which pins layout (shape `(len, W)`)
  — layout is unaffected, order may not be.
- Equality/comparison semantics between sums with different `H`.
- `BuildAccumulator::finalize` must choose a hash. Use
  `desired_bits(n, DEFAULT_TARGET_BUCKET_LEN, min_buckets)` and
  `DEFAULT_HASH_SEED` so the `B = 1` property above holds for small sums.

## Suggested order

1. **§1** — decouple `B` from threads. Small, unblocks §2.
2. **§4** — one representation. Biggest structural change; do it before §2 so
   cosets are built against the final type.
3. **§2** — coset tasks, then in-place. Includes the `support()` bitmask change.
4. **§3** — tie groups. Independent, but do it last so the CSV regeneration and
   the sensitivity-table re-measurement happen once.

## Gotchas that cost time in v0.2

- **`cargo bench` and `cargo test --release` compile lib tests in release mode**,
  where `assert_invariants` is `#[cfg(debug_assertions)]` and vanishes. Test
  modules calling it need `#[cfg(all(test, debug_assertions))]`. v0.1 had the same
  defect in `tests/propagate.rs` and `cargo test --release` never built at all.
- **CI sets `RUSTDOCFLAGS: -D warnings`** in both workflows. An intra-doc link
  from public docs to a `pub(crate)` item fails the build. Replicate the CI
  rustdoc step locally.
- **Benchmark what you changed.** The `apply_layer` bench groups exercise the
  *v0.1* oracle, not the bucketed engine. Paired `apply_layer_bucketed` and
  `thread_scaling_bucketed` groups exist for that reason; a missing pair once
  nearly produced a "no speedup" conclusion while the engine was 8–28× faster.
- **Random coefficients cannot catch tie-breaking bugs.** Symmetric Hamiltonians
  are what produce exact ties. Use `tie_heavy_sum` in
  `engine/bucketed.rs::tie_tests`, which generates only four distinct magnitudes.
- **The Ising example is the end-to-end gate.** 4320 layers of real propagation
  with truncation active, reproducing committed CSVs byte-for-byte. Run it after
  anything that touches the engine or truncation.
- **The v0.1 engine in `engine/sort_merge.rs` is the differential oracle.** Do not
  remove it. `engine/bucketed.rs`'s differential tests compare 17 channels ×
  directions × bucket counts against it, and that is the primary correctness net.
- **No `maturin` or venv on the dev host used for v0.2**, so the PyO3 bindings are
  compile-checked only. `python/paulistrings/tests/test_general_unitary.py` and
  `test_expectation.py` have never been run.
- `docs/examples/img/ising_quench.svg` is stale by <1.8% (no matplotlib
  available); the CSVs are current. See `examples/README.md`.
