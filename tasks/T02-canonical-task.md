# T02 — Canonical 127-qubit heavy-hex kicked-Ising task

Read-only reconnaissance. Goal: one exact, fully specified configuration to share
across the Rust engine, PauliPropagation.jl, and any PauliStrings.jl comparison.

## (a) Circuit

- **Qubits**: `n = 127`.
  `examples/common/circuits.py:37` `HEAVY_HEX_127_PATH` — loaded (never
  hard-coded) from `examples/data/heavy_hex_127.edges`, generated by
  `examples/data/generate_heavy_hex.py`.
- **Connectivity source**: `examples/data/kim2023_observables.json:16`
  (`provenance.qubit_indexing`) states this repo's lattice is the
  **ibm_sherbrooke (FakeSherbrooke)** coupling map, not the paper's own
  `ibm_kyiv` device. This is a deliberate, checked substitution: the same
  file's `provenance.verification` note (line 18) records that the published
  weight-10/weight-17 stabilizer supports are reproduced *exactly* on the
  Sherbrooke map by evolving seeds `Z_13`/`Z_58` five steps at
  `theta_h = pi/2`, which is the computational proxy for index-map agreement.
  No fetched source directly asserts the Kyiv/Sherbrooke maps are identical
  — flagged as verified-by-reproduction, not verified-by-citation.
- **Gate sequence per Trotter step** (`examples/common/circuits.py:200-284`,
  `heavy_hex_kicked_ising`):
  ```
  prod_q          exp(-i * theta_h  * X_q     / 2)   # X layer, "x-then-zz" order: first
  prod_(i,j) in E exp(-i * theta_zz * Z_i Z_j / 2)   # ZZ layer: second
  ```
  Default `order = KICKED_ISING_DEFAULT_ORDER = "x-then-zz"`
  (`circuits.py:100`), matching Kim et al. SI Eq. (4) per the module's own
  citation (`circuits.py:229-232`) and per
  `examples/data/kim2023_observables.json:20` (`circuit.layer_order_note`,
  quoting the SI equation directly: rightmost factor of
  `U(theta_h) = prod R_ZZ(-pi/2) * prod R_X(theta_h)` acts first, i.e. X
  before ZZ). This ordering is load-bearing, not cosmetic: `circuits.py:222-227`
  documents that `"zz-then-x"` gives weight-6/15 stabilizers instead of the
  published weight-10/17, and `python/paulistrings/tests/test_examples_circuits.py`
  is cited as the test that pins this.
- **Entangling gate**: `Circuit.pauli_rotation("ZZ", [a, b], theta_zz)`
  (`circuits.py:281`) — a two-qubit ZZ rotation, one gate per edge, grouped
  into disjoint-support "hardware layers" via `heavy_hex_edge_coloring`
  (`circuits.py:270-273`) unless `color_layers=False`. All ZZ rotations
  commute, so grouping changes truncation order but not the exact answer
  (`circuits.py:245-247`).
- **Rotation convention**: `U = exp(-i * theta * P / 2)`, pinned by
  `python/paulistrings/tests/test_pauli_rotation.py` per
  `circuits.py:11-13`. Consequently every angle in the builder is *twice*
  the physical coefficient.
- **theta_zz (entangler angle)**: `theta_zz = -pi/2` exactly
  (`KICKED_ISING_CLIFFORD_THETA_ZZ = -math.pi / 2`, `circuits.py:66`),
  realizing `exp(+i*(pi/4)*Z_i Z_j)`. Cross-checked against the paper's own
  stated convention in `examples/data/kim2023_observables.json:15`
  (`circuit.theta_zz_note`): the paper fixes
  `theta_J = -2*J*dt = -pi/2` "such that the ZZ rotation requires only one
  CNOT", and in this repo's `exp(-i*theta*P/2)` convention the *same* angle
  is `theta_zz = -pi/2`. Numeric value recorded at
  `examples/data/kim2023_observables.json:13`:
  `"theta_zz": -1.5707963267948966`.
- **theta_h (kick angle), values recommended for the canonical task**:
  `7*pi/32 = 0.6872233929727672` and `5*pi/16 = 0.9817477042468103`
  (`benchmarks/python/bench_c_deep_trotter.py` THETA_POINTS, docstring
  lines ~120-125 and the `THETA_POINTS` tuple ~10 lines below the deep
  cuts discussion). Both sit on the published `k*pi/32` grid used by
  Begušić, Gray & Chan (arXiv:2308.05077) — see PUBLISHED_ANCHOR in the
  same file. The paper itself states only "theta_h is swept between 0 and
  pi/2" with no explicit grid
  (`examples/data/kim2023_observables.json:21`,
  `circuit.theta_h_sweep_note`), so the `pi/32` grid is a third-party
  (Begušić et al.) convention adopted here for external comparability, not
  an IBM-paper value.
- **Depth**: `trotter_steps = 20` is the headline depth
  (`bench_c_deep_trotter.py` module docstring: "up to 20 Trotter steps";
  `STEP_POINTS = (5, 9, 15, 20)`), matching Kim et al.'s stated "we extend
  the circuit depth to 20 Trotter steps (60 CNOT layers)"
  (`examples/data/kim2023_observables.json:29`, `weight_1_z62.source_detail`,
  quoting the paper's main text verbatim). Channel count per step is
  `len(E) + n` (`circuits.py:239`); on this lattice `len(E) = 144` edges
  (`circuit.rs` connectivity file has 144 undirected edges per
  `circuits.py:95` docstring "144 undirected edges").
- **final_x_layer**: `False` for the canonical `Z_62` task (default;
  `final_x_layer=True` is only the separate "modified" Fig. 4a circuit,
  `circuits.py:236-238`).

## (b) Observable

- **`Z_62`**, weight-1, single qubit index **62** in the IBM Eagle
  `0..126` device numbering (`examples/common/observables.py`
  `canonical_z_127()` -> `kim2023_operator("weight_1_z62")`, and
  `examples/data/kim2023_observables.json` `observables.weight_1_z62.support
  = {"62": "Z"}`).
- Matches Kim et al. Fig. 4b exactly:
  `examples/data/kim2023_observables.json:29` quotes the paper verbatim —
  "we ... estimate the theta_h dependence of a weight-1 observable, `<Z62>`,
  in Fig. 4b, in which the causal cone extends over the entire device", and
  "we choose an observable that obtains the expected result `<Z62> = 1` at
  the verifiable theta_h = 0 point." The same entry notes Fig. 3a's weight-1
  case is instead the *average magnetization* `M_z`, not `Z_62` — a
  documented disambiguation, not a risk for this task.
- Index convention: `pauli_string()` in `observables.py` places character
  `i` of a full-length string at qubit `i`, the same left-to-right
  convention `runner.jl` documents as identical on both sides modulo the
  0-based/1-based qubit-number shift (`runner.jl:20-22`: "leftmost character
  is qubit 0 in the schema and qubit 1 in jl — the same left-to-right
  order, so keys map verbatim").
- Coefficient convention is Hermitian throughout: `Y` carries no phase,
  coefficient multiplies the literal string (`observables.py:8-10`,
  `interop.py` header, `runner.jl:31-32`).

## (c) Initial state

- `STATE = "z+"` (`bench_c_deep_trotter.py`, module-level constant next to
  `N_QUBITS` and `DIRECTION`), i.e. the +1 eigenstate of Z on every qubit —
  `crates/paulistrings-py/src/sum.rs:1045,1055`: `"z+" -> ProductState::ZPlus`.
  This is `|0...0>^{\otimes 127}`, matching Kim et al.'s `|0>^{127}` initial
  state (referenced in the paper-quote provenance for the stabilizer
  entries, `kim2023_observables.json` `stabilizer_origin` blocks, which
  describe evolving `Z_13`/`Z_58` "of `|0>^127`").

## (d) Propagation direction

- `DIRECTION = "heisenberg"` (`bench_c_deep_trotter.py`), i.e. the observable
  is evolved backward through the circuit (Heisenberg picture): engine-side,
  `Direction::Heisenberg` reads the channel list **in reverse, using each
  channel's adjoint** (`crates/paulistrings/src/circuit.rs:8`). This is the
  standard Pauli-propagation direction for expectation-value estimation and
  is required, never defaulted, by the shared harness
  (`examples/common/harness.py` docstring: "`direction` — ... Required —
  never defaulted anywhere in this suite (plan §8, D9)").
- The Julia side maps this 1:1: `runner.jl:29-30` —
  `direction "heisenberg" -> jl heisenberg=true (reverse order, U'PU)`;
  `"forward" -> jl heisenberg=false (written order, UPU')`. Confirmed
  load-bearing schema contract, not an assumption.

## (e) Alignment with published sources

Verifiable from local sources, cited above:
- Layer order (X before ZZ), `theta_zz = -pi/2`, and the `Z_62`/20-step/
  weight-1 identification all trace to direct quotes of the Kim et al.
  (2023) Nature paper text and SI, captured with URLs, DOI, and fetch date
  in `examples/data/kim2023_observables.json` (`provenance` block:
  `url`, `supplementary_url`, `doi`, `retrieved: "2026-08-31"`).
- The `weight-10`/`weight-17` stabilizer supports at 5 steps, `theta_h=pi/2`,
  are independently *reproduced* by this repo's own engine
  (`kim2023_observables.json` `provenance.verification`, and
  `python/paulistrings/tests/test_examples_circuits.py`), which is strong
  corroborating evidence that the local implementation's lattice, layer
  order, and sign conventions match the paper's circuit as actually run —
  this reconnaissance did not re-run that test, so it is reported as an
  existing, citable claim rather than freshly re-verified here.
- `<Z_62>` specifically at **20** steps has **no published exact value**
  anywhere located locally: `bench_c_deep_trotter.py`'s `PUBLISHED_ANCHOR`
  dict records that the Begušić/Gray/Chan `exact.csv` companion data
  (arXiv:2308.05077) has a `5a` column (`<Z_62>` at 9 steps) but explicitly
  **no `5b` column** (20 steps), and states this is independent
  corroboration that the paper introducing the accuracy bar also has no
  exact 20-step reference. The 20-step number for this canonical task is
  therefore necessarily a **self-converged** (not exact) reference in any
  campaign built on it — see `bench_c_deep_trotter.py`'s "Reference
  strategy" docstring section for the `_plateau_is_real` convergence
  criterion.

**Explicitly unverifiable in this reconnaissance** (not fabricated, flagged
instead):
- The original Kim et al. Nature 2023 PDF / SI was **not fetched or read
  directly** by this task; every paper quote above is transcribed from
  `examples/data/kim2023_observables.json`'s `source_detail`/`*_note` fields,
  which themselves record the fetch provenance (URL, DOI, retrieval date,
  four corroborating papers). This reconnaissance trusts that provenance
  record rather than re-fetching the PDF.
- Whether the `ibm_sherbrooke` (FakeSherbrooke) coupling map used here is
  literally identical, qubit-for-qubit, to the `ibm_kyiv` device the
  original experiment ran on is **not asserted by any fetched source** — the
  repo's own provenance note says exactly this
  (`kim2023_observables.json:16`) and treats the stabilizer-reproduction
  test as the (indirect, computational) evidence instead.
- The `pi/32` kick-angle grid is a Begušić/Gray/Chan convention for
  cross-paper comparability, not a value stated in the original IBM paper
  itself (which only says "swept between 0 and pi/2",
  `kim2023_observables.json:21`).
- PauliPropagation.jl version: `benchmarks/julia/README.md:7` claims
  "pins PauliPropagation.jl 0.8.2 ... resolved for julia 1.12.6." This was
  checked against the live `benchmarks/julia/Manifest.toml:327-330`, which
  records `git-tree-sha1 = "fe2bc2552caf975532a8b1372bd8bde1e1cd3f3f"` for
  the `PauliPropagation` dependency — the Manifest does not itself print a
  human `0.8.2` version string (Manifest.toml records tree-hashes, not
  semver, for registry packages resolved this way), so the `0.8.2` label in
  the README could not be independently cross-checked against a version
  field in the Manifest in this reconnaissance (no registry lookup was
  performed, per the recursive-search/fetch constraints of this task). The
  git-tree-sha1 is the reproducible, checkable identity regardless of what
  label is attached to it; recommend pinning the campaign write-up to that
  hash rather than the bare "0.8.2" string, or independently resolving the
  hash against the General registry before quoting the version number.
