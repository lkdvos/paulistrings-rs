# v0.4 performance-measurement framework: what landed, and the first baseline

Host: ccqlin038 (2× Xeon Gold 6244, 16c/32t, 2 NUMA nodes, governor
`powersave`, shared box — loadavg 1–2.4 during the campaign). rustc 1.94.0.
Raw data: `benchmarks/results/2026-08-30-ccqlin038/{v04-framework-baseline,
v04-threading-baseline,bandwidth}.txt` + JSON snapshots + three flamegraph
HTMLs. Measurements taken on the framework's own (uncommitted-at-the-time)
tree; the campaign headers record the exact dirty state. All measurements
with the `phase-timing` feature only where stated; criterion numbers are
default-feature builds.

## What landed

- `phase-timing` cargo feature: per-phase counters (`engine/stats.rs`,
  `PhaseStats`) threaded through `LayerScratch`/`CosetScratch`; drained via
  `LayerScratch::take_stats()`; `propagate_with_scratch` is the new public
  entry (and `propagate`'s implementation). Compiled out by default. The
  whole existing suite — the 32-entry fingerprint net, thread/bucket/seed
  bitwise-identity tests, capacity stability — passes with the feature ON.
- The probe: `examples/phase_breakdown.rs` (table/JSON/TSV, RSS, greppable
  `cell` lines). Trotter self-caps its input (untruncated 64-layer TFIM
  measured growing ~600×/pass — see its doc comment).
- `[profile.profiling]` (+ line tables in `bench`); DWARF `perf record`
  verified to resolve fat-LTO-inlined frames (`fill_coset`,
  `gather_local_input_major` show up named).
- `scripts/`: `profile.sh` (offline HTML flamegraphs via perf's built-in
  d3 template), `perf-stat.sh` (IPC, LLC, cycles/string; uncore DRAM GB/s
  with idle-baseline subtraction), `bandwidth.sh` + `crates/membench`
  (ceiling), `bench-campaign.sh` (provenance header + `===` sections +
  JSON snapshots), `criterion-report.py` (snapshot/compare across commits),
  `fit_scaling.py` (Amdahl + USL). Workflow doc: `benchmarks/PROFILING.md`.
- CI: clippy/test/example-build lanes under `--features phase-timing`.
- Bench semantics fix: the bucketed layer + thread-scaling groups now set
  `Throughput::Elements` from the *warmed fixed-point* length, and the
  scaling groups hash at fixed-point size (as `propagate` would). **This
  breaks comparability with v0.3 numbers for those groups**: rotation/32t
  ~6.3 → ~5.0 ms and gu2q/32t ~34 → ~15 ms are bench-condition level shifts
  (larger B from the larger fixed-point term count), not engine changes.
  Recorded in the bench comments at both sites.

## Bandwidth reality check

See `2026-08-30-bandwidth-ceiling-ccqlin038.md`. Short version: **~39 GB/s
read per socket, ~45–49 GB/s both sockets** (2 of 6 channels populated;
HT adds nothing; cross-socket first-touch costs ~half the second socket's
channels). Prior "bandwidth-bound" claims were implicitly against a ~280 GB/s
spec ceiling that this box does not have.

## Phase breakdown at n = 10⁶, W = 2 (probe, 8 layers, AlwaysKeep)

rotation_zz (weight-2 ZZ, fixed point n = 1.50M):

| | 1 thread | 32 threads |
|---|---:|---:|
| wall/layer | 71.9 ms | 4.62 ms |
| coset loop share of wall | 99.9% | 97.8% |
| busy split gather/sort/merge | 39/41/20% | 41/37/21% |
| parallel efficiency | 1.00 | 0.92 |
| strings/s | 2.1e7 | 3.2e8 |

- The engine itself is almost all coset loop; rebucket/permute/recount are
  noise for this channel. At 32t the coset loop moves ≈ 3.2e8 × 48 B ≈
  15 GB/s of key+coeff traffic *before* counting sort/merge passes —
  roughly a third of the measured 45–49 GB/s box ceiling, so rotation at 32t
  is within sight of, but not at, the bandwidth wall.
- Single-thread: sort is the largest busy phase (41%). The flamegraph
  (`flamegraph-probe-rotation_zz-…html`) confirms `sort_phase_tagged` and its
  per-run allocations as the 1t cost center — the v0.3 "single-thread
  rotation ~15% slower than v0.2" item lives here (coset scaffolding + tag
  sort with no parallel payoff).
- Probe self-check: timer overhead 0.3% of wall at 1t, 4.9% at 32t (short
  cosets); readings stay honest.

**gu2q (sqrt-SWAP `GeneralUnitary2Q`) through `propagate` — new finding.**
At 32t: wall 215 ms/layer, of which **rebucket = 159 ms/layer = 74% of
wall** (serial), coset loop only 56 ms (efficiency 0.96, merge-dominated).
Root cause, confirmed with the probe's `terms_in`/`terms_out`: sqrt-SWAP² =
SWAP (a Clifford), so alternate layers cancel exactly back to the original
key set — the term count oscillates with period 2 (~1.0M ↔ ~3.25M at this
input; 200k ↔ ~500k at n=2e5), which crosses a power-of-two bucket boundary,
so `rebucket` runs a full serial O(n) refine+coarsen **every layer**. This is
verbatim the "residual risk … accepted, unmeasured" in `rebucket`'s doc
comment (`bucket/sum.rs`), now measured at 3× the cost of the layer itself.
Criterion never saw it because `bucketed_layer_case` calls
`apply_layer_bucketed` directly, skipping `propagate`'s rebucket. The v0.3
open item ("gu2q 20–45% slower, suspected L2 working set") is about the
coset loop and still stands for the criterion path; this rebucket cost is a
separate, larger effect that dominates any real `propagate` workload with
period-oscillating channels. Fix candidates (not attempted here): a
hysteresis band on `desired_bits`, parallelizing refine/coarsen, or
rebucketing only after truncation actually changes n.

depolarizing: pure `rescale` fast path, 1.40 ms/layer at 32t; criterion
reads 1.37 ms — between v0.2's committed 1.12 and v0.3's anomalous 1.6,
supporting the "machine state" explanation of that anomaly.

trotter (64-layer TFIM step, steady n = 67k): 7.5 s → 2.09 s → 2.21 s at
1/8/32t — retrograde past 8 threads at this small n, consistent with the
scaling fits below (small cosets, coordination dominates).

## Threading (placement matrix, `v04-threading-baseline.txt`)

thread_scaling_bucketed_rotation_1e6, medians:

| t | default | node0 (8c+8HT) | phys16 (2 sockets) | smt16 |
|---|---:|---:|---:|---:|
| 8 | 9.54 ms | 10.09 ms | 9.53 ms | 9.99 ms |
| 16 | 5.42 ms | 8.83 ms | **5.21 ms** | 8.82 ms |
| 32 | 4.99 ms | 9.71 ms (oversub.) | 6.20 ms | 9.71 ms |

- **HT yield ≈ 7%** (9.5 → 8.8 ms adding 8 hyperthreads on one socket);
  **the second socket's memory channels are worth ~1.8×** (8.8 → 5.2 ms at
  t=16). Thread scaling on this box is memory-channel scaling.
- Fits (default placement, today's B): rotation s = 3.1%, USL κ = 0.0011 →
  predicted peak p* ≈ 30; gu2q s = 3.4%, p* ≈ 31. The v0.3-era data fit
  p* ≈ 25 and 16 respectively — the larger fixed-point B genuinely extends
  scaling. Measured serial share from the probe (rebucket+recount+finalize
  over wall) is ~0.1% for rotation — the USL κ (coherence) term, not Amdahl
  serial fraction, is what limits it, matching the bandwidth explanation.

## Gates

- Ising macro run: byte-for-byte CSV determinism **PASS** (also exercised
  under `perf record` and the profiling profile).
- Full suite + fingerprint net green with `phase-timing` on; clippy clean in
  both configurations; criterion deltas vs the previous stored run were
  +1.5–4% on sub-100 µs cases (within the shared-box noise floor, loadavg
  1–2 logged) and are additionally confounded for the three groups with the
  documented semantics change.

## Honest caveats

- Shared box, powersave governor: absolute ms drift day to day; the
  framework's ratio metrics (IPC, cycles/string, % of measured ceiling,
  speedups) are the durable numbers.
- cycles/string is whole-process; treat as an upper bound at these reps.
- The uncore pass is system-wide; idle subtraction is approximate.
- The trotter cell uses the probe's capped input; it probes coordination
  overhead at small n, not throughput.
