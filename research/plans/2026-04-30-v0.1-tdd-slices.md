# v0.1 — TDD Breakdown into Workable Slices

## Context

`paulistrings-rs` is at v0.1 scaffolding: the module layout, types, and trait
surfaces from `research/plans/2026-04-30-v0.1-scope.md` are in place, but most
algorithm bodies are `todo!()` (see CLAUDE.md "Status"). This plan:

1. Splits the v0.1 implementation plan (§13 of the design doc) into small,
   independently testable slices.
2. Codifies test-driven development as the working style for this repo.
3. Starts very simple — earliest slices are one function, a handful of tests,
   no surrounding infrastructure.

This plan is the source of truth for *order of work* and *test contract per
slice*. The design doc remains the source of truth for *what the code does*;
each slice references the relevant `§` section.

## Add to CLAUDE.md: a Testing section (TDD policy)

Insert a new top-level section after "Architecture (big picture)" titled
**"Testing & TDD policy"** with this content:

> Development is test-driven. For each slice in
> `research/plans/2026-04-30-v0.1-tdd-slices.md`:
>
> 1. **Red.** Write the smallest failing test that pins down the behavior.
>    Unit tests live next to the code in `#[cfg(test)] mod tests`. Cross-module
>    behavior goes in `crates/paulistrings/tests/`.
> 2. **Green.** Implement the minimum to pass — `todo!()` becomes real code,
>    nothing more. Don't pre-build helpers for slices not yet started.
> 3. **Refactor.** Only after green. No speculative generalization.
>
> Conventions:
> - Tests assert against hand-computed expected values, not against another
>   `todo!()`-implemented function. Where a reference exists (Pauli algebra
>   identities like `XZ = -iY`, `X` anticommutes with `Z`), encode it as a test.
> - For multi-qubit / multi-word logic, parameterize tests over `W ∈ {1, 2}`
>   so the const-generic surface is exercised early.
> - Property tests (via `proptest`) for algebraic laws once a slice has more
>   than ~5 example tests: associativity of multiplication, sortedness
>   invariant after merge, idempotence of `truncate(0.0)`, etc. Add `proptest`
>   as a dev-dependency only when the first property test is written —
>   not before.
> - Each slice's PR/commit lands tests + impl together; do not merge a slice
>   whose tests are `#[ignore]`d. Remove the `#[ignore]` placeholders in
>   `crates/paulistrings/tests/pauli_string.rs` as their slices land.
> - `cargo test` (workspace) must be green at every slice boundary.
> - Benchmarks (`cargo bench`) follow tests, not the other way around — never
>   tune a `todo!()`.

## Slice ordering

Each slice is "small enough to TDD in one sitting." Slices within a phase are
strictly ordered (later ones depend on earlier). Phases match design doc §13.

### Phase 1 — `PauliString<W>` algebra (§3.1)

**Slice 1.1 — `weight()`** *(start here, simplest possible)*
- File: `crates/paulistrings/src/pauli_string.rs`
- Tests: identity → 0; single-qubit X/Y/Z → 1; multi-word case with bits in
  both `x` and `z` words.
- Impl: `(0..W).map(|i| (self.x[i] | self.z[i]).count_ones()).sum()`.
- Removes the `#[ignore]` on `weight_of_identity_is_zero` in
  `crates/paulistrings/tests/pauli_string.rs:17`.

**Slice 1.2 — Single-qubit constructors for tests**
- New `pub fn x(qubit: u32) -> Self`, `y`, `z` on `PauliString<W>`.
- Justification: every later slice needs human-readable Pauli construction.
  Without it, tests devolve into raw `[u64; W]` literals.
- Tests: `weight(X(3)) == 1`; bit positions correct across word boundary
  (qubit 64 lands in word 1).

**Slice 1.3 — `commutes_with()`**
- Tests: `X` anticommutes `Z`; `X` commutes `Y` (false — `XY = iZ`, they
  anticommute), `X` commutes with itself; `XX` (on qubits 0,1) commutes with
  `ZZ` (parity is even); identity commutes with everything.
- Impl: parity of `popcount(self.x & other.z) ^ popcount(self.z & other.x)`
  summed across words.

**Slice 1.4 — `mul_assign()` returning phase**
- `mul_assign(&mut self, other: &Self) -> u8` mutates `self` in place
  (XORing `(x, z)`) and returns the phase `k` in `0..4` such that the true
  product is `i^k * self_after`. A thin value-returning `mul(self, &Self) ->
  (Self, u8)` wraps it.
- Tests pinning each multiplication-table entry: `X·Z = -iY` (returned phase 3),
  `Z·X = iY` (phase 1), `Y·Y = I` (phase 0), associativity on a 3-element case.
- Impl: XOR `(x, z)`; phase delta is `popcount(self.x & other.z) -
  popcount(self.z & other.x)` mod 4 (with care for unsigned arithmetic).
- Property test (introduce `proptest` here): `(a * b) * c == a * (b * c)`
  on random `PauliString<2>` — `(x, z)` parts equal, and cumulative phases
  (summed mod 4 across the two multiplications on each side) are equal.

### Phase 2 — `PauliSum<W>` storage and bulk ops (§3.2)

**Slice 2.1 — `find()` (binary search)**
- Tests: empty sum → `Err(0)`; hit on first/middle/last; miss with correct
  insertion point; `assert_invariants` runs clean on hand-built sorted sums.
- Foundation for every other `PauliSum` op.

**Slice 2.2 — `scale()`**
- Trivially testable; one-line impl. Slice exists to lock down the SoA
  iteration pattern that later parallel ops will reuse.
- Tests: scale by 0 zeros all coeffs; scale by `i` rotates phases; sort
  invariant preserved.

**Slice 2.3 — `truncate_by_magnitude()`**
- Tests: `eps=0` is no-op; `eps > max(|c|)` empties the sum; mixed case
  preserves sort; `assert_invariants` clean after.
- Compact via `retain` over zipped indices, or a two-pointer scan.

**Slice 2.4 — `add()` (sorted merge)**
- Tests: `a + empty == a`; `a + a == 2a` (deduplication on equal keys);
  cancellation when coefficients sum to 0 drops the term; result satisfies
  `assert_invariants`.
- Linear merge of two sorted SoA streams.
- Property test: `(a + b) + c == a + (b + c)` modulo coefficient tolerance.

### Phase 3 — Ingestion (§8.2)

**Slice 3.1 — `BuildAccumulator::add_term` + `finalize`**
- File: `crates/paulistrings/src/accumulator.rs`.
- `add_term(p: PauliString<W>, phase: u8, c: Complex64)` — caller supplies the
  phase explicitly (typically the value returned by `mul_assign` upstream),
  and the body folds `i^phase` into `c` before the upsert.
- Tests: adding the same key twice sums coefficients; `finalize` produces a
  sorted, deduplicated `PauliSum` (`assert_invariants` clean); a non-zero
  `phase` argument rotates the stored coefficient by the correct `i^k`
  factor; cancellation drops the term.

**Slice 3.2 — `PauliSum::from_strings` test helper**
- Accepts `&[(&str, Complex64)]` like `[("XZI", 1.0.into()), ("IZZ", 0.5.into())]`,
  routes through `BuildAccumulator`. Lives behind `#[cfg(test)]` initially;
  promote to public API once Phase 4+ tests use it pervasively.
- Unblocks every later test that needs a non-trivial `PauliSum` literal.

### Phase 4 — Channel trait + Clifford (§6, partial)

**Slice 4.1 — `OutputBuffer<W>`**
- Tests: push respects `MAX_FANOUT` cap; clear/reuse across calls without
  alloc churn (assert capacity after second use).

**Slice 4.2 — `Channel<W>` trait surface compiles + `IdentityChannel` test
double**
- A no-op channel that emits its input unchanged. Used as a sanity scaffold
  for the engine in Phase 6.
- Tests: applying `Identity` produces exactly one output equal to the input.

**Slice 4.3 — `Clifford1Q` for `H, S, X, Y, Z`**
- File: `crates/paulistrings/src/channel/clifford.rs`.
- Table-driven from the conjugation rules (`H X H = Z`, etc.).
- Tests: each gate × each input Pauli on the active qubit gives the expected
  `(output, phase)`; identity bits outside the support are untouched.

**Slice 4.4 — `Clifford2Q` for `CNOT, CZ, SWAP`**
- Tests against the standard conjugation tables (e.g. `CNOT (X⊗I) CNOT = X⊗X`).
- Same shape as 4.3 but with 16-entry tables.

### Phase 5 — `PauliRotation` channel (§6)

**Slice 5.1 — `PauliRotation` apply**
- `exp(-iθP/2) Q exp(iθP/2)`: if `[P, Q] = 0`, output is `Q` (fanout 1);
  else output is `cos(θ) Q + sin(θ) iPQ` (fanout 2).
- `MAX_FANOUT = 2`.
- Tests: rotation by 0 returns input; rotation by π around `Z` flips `X → -X`
  (sign tracked in coefficient); commuting case fanout-1; anticommuting case
  fanout-2 with correct cos/sin coefficients.

### Phase 6 — Sort-merge engine, single-threaded (§5, §8.1)

**Slice 6.1 — Scan phase**
- Pure data-parallel population of an `n_in × MAX_FANOUT` buffer; no
  bucket/merge yet. Outputs are unsorted but contiguous.
- Tests on a tiny hand-built input + `IdentityChannel` (slice 4.2): output
  equals input. Then with `Clifford1Q::H`: output is the conjugated sum.

**Slice 6.2 — Bucket phase**
- Partition output buffer into `2^(2|support|)` buckets keyed by support bits.
- Tests: every output lands in the bucket whose index matches its support
  bits; within-bucket relative order matches input order; concatenation of
  buckets is sorted (when the input was sorted).

**Slice 6.3 — Merge phase + segmented reduction**
- Adjacent equal keys combine; keys whose merged coefficient is `0` are dropped.
- Tests: pairs that fully cancel are dropped; near-cancellation below a hard
  zero is kept (truncation comes in 6.5); result satisfies
  `assert_invariants`.

**Slice 6.4 — Single-layer `propagate` end-to-end (no truncation)**
- Wire 6.1–6.3 behind `Channel::apply_to_sum(&PauliSum<W>) -> PauliSum<W>`.
- Cross-validation tests: `H` applied to the observable `Z` on 1 qubit gives
  `X`; `CNOT` applied to `Z⊗I` gives `Z⊗Z`; a `PauliRotation(Z, π)` round trip
  is identity.

**Slice 6.5 — Multi-layer `propagate` + `Direction`**
- Iterates a `Circuit<W>` of `Box<dyn Channel<W>>`. Heisenberg mode reverses
  the channel order and applies adjoints.
- Tests: 2-layer circuit `[H, H]` is identity; forward then reverse round-trip
  on a small Pauli rotation circuit returns the input within tolerance.

### Phase 7 — Truncation (§7)

**Slice 7.1 — `keep_term` integrated into merge phase**
- Threads a `&T: TruncationPolicy<W>` through 6.3.
- Tests: with `CoefficientThreshold(eps)`, terms below `eps` are dropped
  during the merge, not after.

**Slice 7.2 — `WeightCutoff`**
- Tests: weight `> k` dropped; equal `== k` kept; weight is `popcount(x|z)`
  (reuses slice 1.1).

**Slice 7.3 — `TopN` via `finalize_layer`**
- Tests: a sum of 10 terms truncated to 3 keeps the 3 largest by `|coeff|`;
  result still satisfies `assert_invariants`.
- (`And` / `Or` combinators are already implemented per CLAUDE.md "Status";
  add tests if missing.)

### Phase 8 — Parallelism (§9)

**Slice 8.1 — Rayon scan**
- Switch slice 6.1 to `par_iter`. Behavior unchanged; tests from 6.1 must
  still pass. Add a determinism test: same input → byte-identical output
  across thread counts.

**Slice 8.2 — Chunked segment-aware merge**
- Per design doc §9. Boundary reconciliation pass between chunks.
- Tests: 6.3's tests must still pass; add a stress case where a duplicate key
  spans a chunk boundary.

### Phase 9 — Noise channels (§6, §13 step 7)

## Verification

- Per slice: `cargo test -p paulistrings <slice-name-substring>` green;
  `cargo test` workspace green; `cargo clippy --all-targets -- -D warnings`
  clean.
- Per phase boundary: hand-run a tiny end-to-end script demonstrating the
  newly-unlocked capability — e.g. after Phase 6, a 3-line example that
  conjugates `Z` through `H` and prints `X`.
- After Phase 10.1, `maturin develop --release -m crates/paulistrings-py/Cargo.toml`
  installs and `pytest python/paulistrings/tests/` is green.
- Benchmarks (Phase 11) only run `--release`, per CLAUDE.md "Benchmark
  conventions".
