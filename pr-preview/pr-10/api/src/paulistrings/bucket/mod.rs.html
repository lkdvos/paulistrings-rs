1//! GF(2)-linear bucket partitioning of a Pauli sum. See ARCHITECTURE.md §Bucketing.
2//!
3//! The propagation engine does not maintain one global sorted order. Instead
4//! the sum is partitioned by a GF(2)-linear hash `h(v) = H·v` of the Pauli key.
5//! Two properties make that partition useful, and both follow from linearity:
6//!
7//! * A channel maps an input key to `v ⊕ d` for `d` in a small **delta set**, so
8//!   `h(v ⊕ d) = h(v) ⊕ h(d)` — output buckets are predictable from input
9//!   buckets, and because `⊕` is an involution the relation inverts: each
10//!   *output* bucket gathers from a statically-known handful of input buckets
11//!   (1, 2, 4 or 16 for the built-in channels).
12//! * `h` is a function, so equal keys always land in the same bucket.
13//!   Deduplication is therefore bucket-local, and **there is no global sort**.
14//!
15//! [`hash`] defines the hash `Gf2Hash<W>` itself — the linear map, its delta
16//! set, and the bit-count policy (`desired_bits`) that ties bucket count to
17//! term count. [`sum`] holds the bucketed storage: `PauliSum<W>`'s
18//! column layout and the `refine`/`coarsen`/`rebucket` operations that keep
19//! the bucket count matched to the sum as it grows or shrinks. There is one
20//! `PauliSum` type, not a separate flat and bucketed form — a sum small
21//! enough to live in a single bucket is, by construction, plain lex-sorted.
22
23pub mod hash;
24pub mod sum;
25
26pub use hash::{Gf2Hash, PartitionRows, B_MAX_BITS, P_MAX_BITS};
27pub use sum::{
28    desired_bits, DEFAULT_HASH_SEED, DEFAULT_MIN_BUCKETS, DEFAULT_TARGET_BUCKET_LEN,
29    MIN_TERMS_PER_TASK,
30};
